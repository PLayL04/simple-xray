# SimpleVpn — концепция и архитектура

> Рабочее название: **SimpleVpn**. Статус: M0–M4 готовы (2026-11-11), далее M5.

## 1. Что это за приложение

Клиент для прокси-сервера на Xray (VLESS и др., серверная часть — 3x-ui), который:

- для пользователя выглядит так же просто, как Amnezia VPN: **одна большая кнопка «Подключить / Отключить»**, выбранный сервер и статус;
- внутри сохраняет гибкость v2rayN: пресеты маршрутизации, автообновляемые geo-базы (geoip/geosite), режим системного прокси или TUN;
- все сложные параметры убраны в настройки и имеют разумные значения по умолчанию, так что пользователь может туда вообще не заходить.

Целевая аудитория — друзья администратора сервера, не технические пользователи. Администратор передаёт им ссылку `vless://` или QR-код, они импортируют её и нажимают кнопку.

### Платформы

| Платформа | Приоритет | Комментарий |
|---|---|---|
| Windows 10/11 x64 | **Основная** | MVP делается только под неё |
| Android | Позже | Общие ядро логики и ViewModel, отдельный UI под сенсорный экран |
| macOS / iOS / Linux | Не планируются | Архитектура не должна их исключать, но специально под них ничего не делаем |

### Вне рамок проекта (на текущем этапе)

- Подписки 3x-ui (subscription URL): модель данных их предусматривает, но в MVP не входят.
- Раздельное туннелирование по приложениям (per-app): реализуется позже, архитектура это учитывает (см. §5.4).
- Автообновление самого приложения: распространяется вручную.
- Другие ядра (sing-box, mihomo).

### 2.2 Почему ядро — Xray, а не mihomo или sing-box

- **XHTTP** (используется на сервере: VLESS + XHTTP + TLS) полностью поддерживается только в Xray. В sing-box его нет, в mihomo поддержка неполная и отстаёт от изменений протокола.
- Сервер работает на Xray (3x-ui), поэтому клиент на том же ядре гарантированно совместим со всеми транспортами, которые администратор включит в будущем: Reality, XHTTP, WS, gRPC, Vision и т.д.
- В Xray теперь есть **собственный TUN inbound** (Windows через Wintun, Linux, Android). Отдельный tun2socks или sing-box для TUN, как в v2rayN, не нужен, хватает одного ядра.
- В правилах маршрутизации Xray есть поле **`process`** (Windows/Linux, на Android — по UID). Это задел для per-app маршрутизации без смены ядра.
- Формат `geoip.dat` / `geosite.dat` нативен для Xray, и готовые российские списки (runetfreedom) выпускаются именно в нём.

Минус: Xray не умеет загружать rule-providers на лету, как mihomo. Поэтому обновлением geo-файлов управляет само приложение (§6), и после обновления ядро быстро перезапускается.

### 2.4 Как подключать Xray

- **Windows:** `xray.exe` запускается как дочерний процесс с конфигом, который генерирует приложение (`run -c config.json`). Приложение читает stdout/stderr в лог, следит за процессом (если он упал, показывает ошибку и откатывает системный прокси) и при выходе убивает процесс через Job Object, чтобы xray не остался «сиротой».
- Версия Xray **зафиксирована** (pinned) в репозитории (`tools/xray-version.txt`) и скачивается скриптом `tools/fetch-xray.ps1` вместе с `wintun.dll`. Ядро обновляет разработчик вручную, после проверки совместимости параметров XHTTP.
- Статистика (скорость, трафик) — через gRPC Stats API Xray. В MVP не входит.
- **Android (позже):** VpnService создаёт TUN и передаёт fd в Xray. Нужно отдельно проверить: (а) libXray / AndroidLibXrayLite (gomobile AAR, используется в v2rayNG) с биндингом в .NET for Android или (б) бинарник xray с TUN inbound, которому передаётся fd.

## 4. Режимы подключения (Windows)

### 4.1 Системный прокси (по умолчанию)

- Xray поднимает inbound'ы `socks` и `http` на `127.0.0.1` (порты по умолчанию 10888/10889 — не 10808/10809, чтобы не конфликтовать с запущенным v2rayN; при занятости выбирается свободный).
- Готовность ядра определяется по тому, что SOCKS-порт начал принимать соединения (таймаут 10 с); если процесс завершился раньше — ошибка `CoreExited` с выводом xray в логе.
- Прокси выставляется через WinINet per-connection API (флаги, сервер, исключения, PAC, автоопределение) для LAN-подключения; снимок прежних настроек сохраняется целиком и восстанавливается побайтно (проверено на реальной системе).
- `xray.exe` запускается в Job Object с `KILL_ON_JOB_CLOSE`: если приложение упадёт или будет убито, ОС сама завершит ядро.
- Приложение включает системный прокси WinINet и задаёт список исключений (`localhost;127.*;10.*;172.16.*-172.31.*;192.168.*;<local>`), затем вызывает `InternetSetOption(INTERNET_OPTION_SETTINGS_CHANGED / REFRESH)`.
- **Восстановление после сбоя:** перед включением прокси сохраняются прежние настройки и ставится флаг `proxyApplied` в `state.json`. Если при старте флаг найден, а ядро не запущено, прежние настройки прокси восстанавливаются. Так у пользователя не «пропадёт интернет», если приложение упало.
- Ограничение: прокси используют не все программы (игры, часть клиентов). Для них нужен режим TUN.

### 4.2 VPN (TUN)

- Используется `tun` inbound Xray (`wintun.dll` рядом с `xray.exe`). Ключи сверены с исходниками v26.11.9:
  - `name: "SimpleVpn"`, `mtu: 1500`, `gateway: ["172.19.0.1/30", "fdfe:dcba:9876::1/126"]`, `dns: ["172.19.0.2"]`;
  - `autoSystemRoutingTable: ["0.0.0.0/0", "::/0"]` — Xray сам ставит маршруты и снимает их при выходе;
  - `autoOutboundsInterface: "auto"` — собственные сокеты Xray привязываются к физическому интерфейсу, поэтому петли нет;
  - `autoSystemWfpBlockLeak: ["dns"]` (настройка «Блокировать утечки DNS», по умолчанию вкл.) — WFP-фильтры в динамической сессии, исчезают вместе с процессом.
- Inbound'ы SOCKS/HTTP остаются (нужны загрузчику geo через прокси), системный прокси в TUN-режиме **не трогается**.
- Успех подключения — когда адаптер `SimpleVpn` появился в системе и поднят (`INetworkProbe.WaitForInterfaceAsync`). Иначе `TunFailed` (или `CoreExited`, если ядро упало), ядро останавливается.
- **Права:** приложение запускается без прав администратора (`asInvoker`). `ConnectionManager` без прав сразу возвращает `ElevationRequired`, не запуская ядро. Главный экран показывает диалог: «Перезапустить от администратора» (`runas` с `--connect --elevated-restart`, остальные аргументы вроде `--lang` пробрасываются), «Подключить через прокси» (переключает режим и подключается) или «Отмена». Отказ в UAC оставляет диалог с пояснением. Новый экземпляр с `--elevated-restart` ждёт до 15 с, пока старый освободит mutex, а `--connect` подключает сразу после показа окна. Опция «Всегда запускать от администратора» будет позже (автозапуск через Планировщик заданий).
- Ограничение: если обычный пользователь вводит в UAC учётку другого администратора, повышенный экземпляр работает под другим профилем (другой `%APPDATA%`, без серверов). Портативный режим это не затрагивает.
- Переключение режима при подключении: `ReconnectIfConnectedAsync` видит смену режима, полностью откатывает старый (включая системный прокси) и подключается заново.
- DNS в TUN-режиме: запросы на порт 53 из `tun-in` идут в outbound `dns` (`dns-out`) — встроенный DNS Xray со своими правилами (§5.3). Системный резолвер для прямых доменов (`localhost`) Xray вызывает в обход TUN: Go-резолвер пропускает DNS-серверы самого TUN-адаптера.

## 5. Маршрутизация

### 5.1 Модель данных

```jsonc
// RoutingPreset (Core/Routing/RoutingPreset.cs); тот же формат у встроенных, пользовательских и экспортированных
{
  "schemaVersion": 1,
  "id": "bypass-ru",                        // у пользовательских — "user-xxxxxxxx" = имя файла
  "name": "All except RU",                  // запасное имя
  "names": { "ru": "Всё, кроме RU", "en": "All except RU" },  // локализованные (у встроенных)
  "domainStrategy": "IPIfNonMatch",         // AsIs | IPIfNonMatch | IPOnDemand
  "rules": [
    { "name": "Local network", "domain": ["geosite:private"], "ip": ["geoip:private"], "outbound": "direct" },
    { "domain": ["geosite:ru-blocked"], "outbound": "proxy" },
    { "ip": ["geoip:ru"], "outbound": "direct" }
  ],
  "defaultOutbound": "proxy",               // всё, что не попало в правила
  "sourceUrl": "https://…"                  // если импортирован по ссылке — можно «Обновить с источника»
}
```

Правило — подмножество полей Xray: `domain`, `ip`, `port`, `network`, `protocol`, `process` плюс `enabled`, `name` (комментарий) и `outbound ∈ {proxy, direct, block}`. Правила проверяются сверху вниз, срабатывает первое подходящее.

Как `XrayConfigBuilder` переводит пресет в `routing`:
- **Домены и IP внутри одного правила — это варианты (ИЛИ).** В Xray поля одного правила объединяются через И, поэтому правило с `domain` и `ip` разбивается на два правила Xray. `port`, `network`, `protocol` и `process` добавляются к каждому из них и сужают условие (И).
- Выключенные правила (`enabled: false`) пропускаются.
- В конец добавляется правило `network: "tcp,udp" → defaultOutbound`: иначе Xray отправил бы несовпавший трафик в первый outbound (proxy).
- Первыми идут служебные правила для запросов встроенного DNS Xray (см. §5.3).

`PresetValidator` проверяет пресет до сохранения и использования: имя, `domainStrategy`, у каждого правила есть хотя бы одно условие, префиксы доменов (`geosite:`, `domain:`, `full:`, `keyword:`, `regexp:` с компиляцией, `ext:`, `dotless:` или обычная подстрока), IP/CIDR (биты хоста допускаются, как в Xray), `geoip:`/`!geoip:`/`ext:`, списки портов, сеть, протоколы. Ошибки — коды `PresetError` с номером правила; UI показывает текст из `PresetError_<Code>`. Существование категорий geosite/geoip проверяет сам Xray: тест прогоняет все встроенные пресеты через `xray run -test` с настоящими geo-файлами.

### 5.2 Встроенные пресеты

Категории сверены с runetfreedom/russia-v2ray-rules-dat (2026-11): `geosite:category-ru` уже включает `tld-ru` (.ru/.su/.рф); `geosite:ru-blocked` (~74 тыс. доменов) покрывает YouTube, Discord, Instagram, X, OpenAI/ChatGPT, Telegram; `ru-blocked-all` (1,6 млн) слишком велик для пресета по умолчанию; `ru-available-only-inside` — российские сервисы, которые работают только изнутри страны (Госуслуги, Яндекс и т.п.). В geoip есть `ru`, `ru-blocked`, `ru-blocked-community`, `telegram`, `private`.

| Пресет | Правила (по порядку) | Остальное | По умолчанию |
|---|---|---|---|
| **Всё через прокси** (`global`) | private → direct | proxy | |
| **Всё, кроме RU** (`bypass-ru`) | private → direct; `ru-available-only-inside` → direct; `geosite:ru-blocked` → proxy (заблокированные сайты даже в .ru); `geosite:category-ru` → direct; `geoip:ru-blocked` → proxy; `geoip:ru` → direct | proxy | ✅ |
| **Только заблокированное** (`blocked-only`) | private → direct; `ru-available-only-inside` → direct; `geosite:ru-blocked` / `geoip:ru-blocked` → proxy; `geoip:telegram` → proxy | direct | |

Реклама не блокируется: блокировка `category-ads-all` ломает часть сайтов, а приложение для нетехнических пользователей. Желающие добавят правило в своём пресете.

Встроенные пресеты — ресурсы сборки `Core/Routing/Presets/*.json` (`BuiltInPresets`). Их нельзя изменить или удалить, только **дублировать**. Копия открывается в редакторе. Пользовательские пресеты — `presets\<id>.json` в папке настроек (`PresetRepository`): имя файла — это id, поэтому файл можно подложить и вручную; повреждённые файлы пропускаются с записью в лог. Активный пресет хранится в `settings.json` (`selectedPresetId`); если id неизвестен, используется `bypass-ru`.

Импорт и экспорт — JSON-файл или URL (`HttpDownloader`: сначала напрямую, при ошибке — через запущенное ядро; не больше 1 МБ). У пресета, импортированного по ссылке, сохраняется `sourceUrl`; кнопка «Обновить с источника» заменяет правила, сохраняя id и имя. Так администратор раздаёт друзьям свой пресет. Импортированный пресет не включается сам — пользователь нажимает «Использовать».

### 5.3 DNS

Секция `dns` генерируется вместе с пресетом (`DnsSettings` в `settings.json`):
- **удалённый DNS** (по умолчанию `https://1.1.1.1/dns-query`) — его запросы идут через прокси: служебное правило `inboundTag: ["dns-module"] → proxy`;
- **прямой DNS** (по умолчанию `localhost` — системный резолвер; он вообще не проходит через маршрутизацию Xray). Можно указать IP-адрес, тогда добавляется правило `inboundTag + ip → direct`;
- какому серверу какие домены: если остальной трафик идёт через прокси, домены из direct-правил (`geosite:category-ru` и т.п., кроме `geosite:private`) разрешает прямой DNS, всё прочее — удалённый. Для пресета «Только заблокированное» наоборот: proxy-домены разрешает удалённый DNS, остальное — прямой. Учитываются только правила без дополнительных условий (порт, сеть и т.д.);
- `queryStrategy: UseIPv4` по умолчанию (настройка «Только IPv4»), иначе `UseIP`.

В режиме системного прокси браузер передаёт прокси имя хоста, поэтому DNS Xray нужен в основном для `IPIfNonMatch` (проверить IP-правила для доменов, не попавших в доменные правила). В TUN он основной резолвер: перехват порта 53 → outbound `dns`.

### 5.4 Применение изменений на лету

Смена сервера, пресета или настроек при активном подключении вызывает `ReconnectIfConnectedAsync`. Он перезапускает только ядро: останавливает xray, генерирует новый конфиг и запускает xray на **тех же портах**. Системный прокси не трогается, UI показывает «Подключение…», но не «Отключено». Если HTTP-порт оказался занят, прокси переставляется на новый, а исходный снимок пользователя в `state.json` сохраняется. Если ядро не поднялось — полный откат, как при ошибке подключения. Новые порты из настроек применяются со следующего подключения.

### 5.5 Задел под per-app (позже)

- В модели правил уже есть поле `process`, Xray поддерживает его на Windows и Linux (на Android — по UID).
- Правила по процессам имеют смысл только в TUN-режиме. В режиме прокси UI будет предупреждать об этом.
- UI: выбор запущенного процесса или .exe-файла.

## 6. Geo-базы и автообновление

Реализовано в `Core/Geo`: `GeoUpdater` обновляет базы, `GeoUpdateScheduler` запускает проверки по расписанию, `GeoDatFile` читает и проверяет файлы. Настройки — `GeoSettings` в `settings.json`, состояние — `geo-state.json` в папке данных.

- **Источник:**
  - по умолчанию — `runetfreedom/russia-v2ray-rules-dat`, `releases/latest/download/{geoip,geosite}.dat`; рядом обязательно лежат `.sha256sum`;
  - свой источник — две ссылки на `geoip.dat` и `geosite.dat`. Файл `<ссылка>.sha256sum` необязателен: при 404 проверка суммы пропускается.
- **Когда:**
  - фоновая проверка через 30 с после старта, затем каждый час — если включено автообновление и с последней успешной проверки прошёл интервал (6 ч / 12 ч / **1 день** / 3 дня / неделя);
  - неудачная проверка не сдвигает время, поэтому повторяется через час;
  - кнопка «Обновить сейчас» проверяет без учёта интервала;
  - ручная и фоновая проверки не пересекаются: фоновая перепроверяет «пора ли» после ожидания.
- **Как обнаруживаются изменения:**
  - вместо условного GET скачивается маленький `.sha256sum` и сравнивается с sha256 локального файла. Ссылки `latest/download` ведут через редирект на подписанные одноразовые URL, а релизы выходят несколько раз в день, поэтому ETag и `If-Modified-Since` здесь ненадёжны;
  - без контрольной суммы (свой источник) файл скачивается целиком и сравнивается по содержимому.
- **Безопасная установка** (всё или ничего):
  1. Загрузка во временный файл `*.download` (до 300 МБ; таймаут 60 с без данных; частичный файл удаляется). Прогресс показывается в UI.
  2. Проверка sha256 → разбор структуры protobuf (`GeoDatFile`: верхний уровень, записи пропускаются по длине, 100 МБ за миллисекунды) → **проверка, что в новой базе есть все категории geosite/geoip, которые используют встроенные пресеты и активный пресет**. Иначе обновление отклоняется (`MissingCategory`), прежние базы остаются.
  3. `File.Replace` с `.bak`; если не удалось заменить второй файл, первый восстанавливается.
  4. Если подключение активно — перезапуск ядра на месте (§5.4). Если ядро не поднялось — `.bak` возвращаются, подключение восстанавливается, ошибка `CoreRejected`.
- Ошибки — `GeoUpdateError` (`InvalidSource`, `DownloadFailed`, `ChecksumMismatch`, `InvalidFile`, `MissingCategory`, `ReplaceFailed`, `CoreRejected`). В UI они показываются через `GeoError_<Code>`, в лог пишутся с деталями.
- **Если GitHub недоступен:** `HttpDownloader` сначала скачивает напрямую, при сетевой ошибке или ответе 5xx — через запущенное ядро (`127.0.0.1:<http-порт>`). Ответ 4xx окончательный.
- Проверено вживую при активном подключении: обновление ~100 МБ заняло ~20 с, xray перезапустился с новыми файлами (Windows не блокирует замену, xray держит базы в памяти), повторная проверка вернула «актуальны» без загрузки.
- В сборку входит начальная копия geo-файлов, поэтому приложение работает сразу после установки, без сети. Скачиваются только `.dat`-файлы, а не исполняемый код: скомпрометированный источник подменит только списки, но не сможет выполнить код.

## 7. Импорт серверов

- Парсер `vless://` (`VlessLinkParser`) поддерживает: `security=tls|reality|none`, `type=tcp|xhttp|ws|grpc|httpupgrade`, `sni`, `fp`, `alpn`, `pbk`, `sid`, `spx`, `flow`, `path`, `host`, `mode`, `extra` (JSON для XHTTP), `#имя`.
- Неизвестные параметры сохраняются в профиле как есть, чтобы не терять их при экспорте обратно в ссылку.
- `allowInsecure` удалён в Xray 26 (запуск с ним падает). Флаг из ссылки сохраняется только для экспорта; для самоподписанных сертификатов поддерживаются `pcs` (`pinnedPeerCertSha256`) и `vcn` (`verifyPeerCertByName`).
- Повторный импорт ссылки на тот же сервер (адрес + порт + UUID) обновляет существующий профиль, а не создаёт дубликат.
- Источники: вставка текста, буфер обмена (проверяется при открытии окна добавления), QR-код из файла-картинки или со снимка экрана (ZXing.Net).
- Архитектурный задел: интерфейс `IProfileSource` → `LinkSource` (сейчас) и `SubscriptionSource` (позже, 3x-ui subscription, base64-список ссылок). Позже можно добавить `vmess://`, `trojan://`, `ss://`.

### Ключевой поток «Подключить»

```
UI (кнопка) → ConnectionManager.ConnectAsync()
  → проверка: выбран профиль? geo-файлы есть? для TUN — есть права? (иначе → IElevation)
  → XrayConfigBuilder.Build(profile, preset, mode, settings) → config.json
  → ICoreRunner.Start(config)  → ждём, пока inbound поднимется (порт слушается / TUN-адаптер создан)
  → mode == Proxy ? ISystemProxy.Enable(port) : —
  → State = Connected
```
Отключение выполняется в обратном порядке. При любой ошибке — откат того, что успело примениться.

## 9. Хранение данных

| Что | Где |
|---|---|
| Настройки, профили, пользовательские пресеты | `%APPDATA%\SimpleVpn\` (`settings.json`, `profiles.json`, `presets\`) |
| Geo-файлы, сгенерированный конфиг, логи, `state.json` | `%LOCALAPPDATA%\SimpleVpn\` |
| Бинарники (xray.exe, wintun.dll) | рядом с приложением (`core\`) |

Режим portable: если рядом с exe лежит файл `portable`, всё хранится в `.\data\`.
UUID в профилях — секрет: в логи не пишется. Access-лог Xray выключен (`"access": "none"`), чтобы история посещённых сайтов не попадала на диск.

## 11. Риски и открытые вопросы

- **Антивирусы** могут ругаться на `xray.exe` и неподписанное приложение. Нужна инструкция для друзей; позже — подпись кода.
- **Изменения XHTTP** между версиями Xray: клиент и сервер (3x-ui) должны быть совместимы. Поэтому версия ядра фиксируется, обновление ядра — осознанный шаг.
- **TUN и аварийное завершение xray** проверены вживую 2026-11-11. После `kill` xray адаптер и маршрут исчезают меньше чем за 3 с, «weak host send» на физическом интерфейсе не меняется, интернет работает, а приложение показывает ошибку «ядро остановилось». Ещё не проверены трафик через настоящий сервер в TUN и кнопка перезапуска через UAC.
- **Android:** нужно выбрать способ встраивания Xray (AAR через биндинг или бинарник с передачей fd) — исследование перед M6.
- **Категории geo-баз могут меняться** в источнике. Тест `Build_ProducesConfigAcceptedByXray` для каждого встроенного пресета ловит пропавшую категорию с текущими файлами. При автообновлении (M3) новая база без нужных категорий отклоняется, а отказ ядра откатывает файлы из `.bak`.
- **Завершение сеанса Windows при подключении** (выход, выключение ПК): прокси восстанавливается только при следующем запуске приложения. Нужно обработать WM_QUERYENDSESSION — в M5 вместе с треем и автозапуском.
- **Размер сборки** ~240 МБ (из них geo ~105 МБ, Xray ~35 МБ). Позже: триминг .NET, архив для раздачи, возможно — не класть geo в сборку, а качать при первом запуске.
- **Финальное название** приложения.
