# SimpleVpn — концепция и архитектура

> Рабочее название: **SimpleVpn**. Статус: M0 (каркас) готов (2026-11-11), далее M1.

## 1. Что это за приложение

Клиент для прокси-сервера на Xray (VLESS и др., серверная часть — 3x-ui), который:

- для пользователя выглядит так же просто, как Amnezia VPN: **одна большая кнопка «Подключить / Отключить»**, выбранный сервер и статус;
- внутри сохраняет гибкость v2rayN: пресеты маршрутизации, автообновляемые geo-базы (geoip/geosite), режим системного прокси или TUN;
- все сложные параметры убраны в настройки и имеют разумные значения по умолчанию, так что пользователь может туда вообще не заходить.

Целевая аудитория — друзья администратора сервера, не технические пользователи. Администратор передаёт им ссылку `vless://` или QR-код, они импортируют её и нажимают кнопку.

### Платформы

| Платформа | Приоритет | Комментарий |
|---|---|---|
| Windows 10/11 x64 | **Основная** | MVP делается только под неё |
| Android | Позже | Общие ядро логики и ViewModel, отдельный UI под сенсорный экран |
| macOS / iOS / Linux | Не планируются | Архитектура не должна их исключать, но специально под них ничего не делаем |

### Вне рамок проекта (на текущем этапе)

- Подписки 3x-ui (subscription URL): модель данных их предусматривает, но в MVP не входят.
- Раздельное туннелирование по приложениям (per-app): реализуется позже, архитектура это учитывает (см. §5.4).
- Автообновление самого приложения: распространяется вручную.
- Другие ядра (sing-box, mihomo).

## 2. Выбор стека

### 2.1 Итоговое решение

| Слой | Выбор |
|---|---|
| Язык | **C# / .NET 10 (LTS)** |
| UI | **Avalonia 12** + MVVM (CommunityToolkit.Mvvm) |
| Ядро | **Xray-core** (отдельный процесс `xray.exe`, на Android — библиотека или бинарник) |
| TUN | Встроенный в Xray `tun` inbound + `wintun.dll` |
| Системный прокси | WinINet (`InternetSetOption`) / реестр через P/Invoke |
| QR-коды | ZXing.Net |
| Хранение настроек | JSON-файлы (System.Text.Json, source generators) |
| Локализация | `.resx` (RU по умолчанию, EN) |
| Тесты | xunit.v3 на Microsoft.Testing.Platform |
| Сборка | `dotnet publish` self-contained win-x64, portable-zip (позже — установщик Inno Setup) |

### 2.2 Почему ядро — Xray, а не mihomo или sing-box

- **XHTTP** (используется на сервере: VLESS + XHTTP + TLS) полностью поддерживается только в Xray. В sing-box его нет, в mihomo поддержка неполная и отстаёт от изменений протокола.
- Сервер работает на Xray (3x-ui), поэтому клиент на том же ядре гарантированно совместим со всеми транспортами, которые администратор включит в будущем: Reality, XHTTP, WS, gRPC, Vision и т.д.
- В Xray теперь есть **собственный TUN inbound** (Windows через Wintun, Linux, Android). Отдельный tun2socks или sing-box для TUN, как в v2rayN, не нужен, хватает одного ядра.
- В правилах маршрутизации Xray есть поле **`process`** (Windows/Linux, на Android — по UID). Это задел для per-app маршрутизации без смены ядра.
- Формат `geoip.dat` / `geosite.dat` нативен для Xray, и готовые российские списки (runetfreedom) выпускаются именно в нём.

Минус: Xray не умеет загружать rule-providers на лету, как mihomo. Поэтому обновлением geo-файлов управляет само приложение (§6), и после обновления ядро быстро перезапускается.

### 2.3 Почему C# + Avalonia

Вы знаете Python, C# и немного C++.

| Вариант | За | Против |
|---|---|---|
| **C# + Avalonia** ✅ | Знакомый язык; Windows и Android из одной кодовой базы; общие ViewModel при разных View для десктопа и телефона; на Avalonia работает кроссплатформенная версия v2rayN — можно подглядывать решения | Android-слой (VpnService) придётся писать на .NET for Android, это сложнее, чем на Kotlin |
| C# + WPF | Самый зрелый UI на Windows, v2rayN под Windows сделан на нём | Нет Android: мобильную версию пришлось бы писать с нуля |
| .NET MAUI | Официальный кроссплатформенный фреймворк Microsoft | Слабый десктоп, нет нормальной поддержки трея, нестабилен |
| Flutter (Dart) | Отличный мобильный UI, на нём сделан Hiddify | Новый язык; интеграция с Xray через FFI/платформенные каналы; десктопные фичи (трей, системный прокси) только через плагины |
| Tauri (Rust + Web) | Лёгкий, красивый UI | Два новых языка; Android-поддержка сырая |
| Python (PySide/Qt) | Самый знакомый язык | Тяжёлая упаковка, ложные срабатывания антивирусов на сборках PyInstaller, Android практически недоступен |

### 2.4 Как подключать Xray

- **Windows:** `xray.exe` запускается как дочерний процесс с конфигом, который генерирует приложение (`run -c config.json`). Приложение читает stdout/stderr в лог, следит за процессом (если он упал, показывает ошибку и откатывает системный прокси) и при выходе убивает процесс через Job Object, чтобы xray не остался «сиротой».
- Версия Xray **зафиксирована** (pinned) в репозитории (`tools/xray-version.txt`) и скачивается скриптом `tools/fetch-xray.ps1` вместе с `wintun.dll`. Ядро обновляет разработчик вручную, после проверки совместимости параметров XHTTP.
- Статистика (скорость, трафик) — через gRPC Stats API Xray. В MVP не входит.
- **Android (позже):** VpnService создаёт TUN и передаёт fd в Xray. Нужно отдельно проверить: (а) libXray / AndroidLibXrayLite (gomobile AAR, используется в v2rayNG) с биндингом в .NET for Android или (б) бинарник xray с TUN inbound, которому передаётся fd.

## 4. Режимы подключения (Windows)

### 4.1 Системный прокси (по умолчанию)

- Xray поднимает inbound'ы `socks` и `http` на `127.0.0.1` (порты по умолчанию 10808/10809, при занятости выбирается свободный).
- Приложение включает системный прокси WinINet и задаёт список исключений (`localhost;127.*;10.*;172.16.*-172.31.*;192.168.*;<local>`), затем вызывает `InternetSetOption(INTERNET_OPTION_SETTINGS_CHANGED / REFRESH)`.
- **Восстановление после сбоя:** перед включением прокси сохраняются прежние настройки и ставится флаг `proxyApplied` в `state.json`. Если при старте флаг найден, а ядро не запущено, прежние настройки прокси восстанавливаются. Так у пользователя не «пропадёт интернет», если приложение упало.
- Ограничение: прокси используют не все программы (игры, часть клиентов). Для них нужен режим TUN.

### 4.2 VPN (TUN)

- Используется `tun` inbound Xray с `wintun.dll` рядом с `xray.exe`, а также опции `autoSystemRoutingTable` и `autoOutboundsInterface` против петель маршрутизации. Перед реализацией нужно сверить точные ключи с документацией Xray для зафиксированной версии.
- **Права:** приложение запускается без прав администратора (`asInvoker`). Когда пользователь выбирает TUN и нажимает «Подключить» без прав, приложение предлагает перезапуститься от администратора (`ShellExecute` с verb `runas`, аргумент `--connect`). После UAC приложение стартует и сразу подключается. Опция «Всегда запускать от администратора» будет позже (автозапуск через Планировщик заданий).
- DNS в TUN-режиме: перехват DNS (порт 53) направляется во встроенный DNS Xray, чтобы избежать утечек; русские домены резолвятся через прямой DNS, остальные — через прокси (DoH). Детали в §5.3.

## 5. Маршрутизация

### 5.1 Модель данных

```jsonc
// RoutingPreset
{
  "id": "bypass-ru",
  "name": { "ru": "Всё, кроме RU", "en": "All except RU" },
  "builtIn": true,                 // встроенные нельзя изменить, только дублировать
  "domainStrategy": "IPIfNonMatch",
  "rules": [
    { "type": "field", "domain": ["geosite:private"], "ip": ["geoip:private"], "outbound": "direct" },
    { "domain": ["geosite:category-ads-all"], "outbound": "block" },
    { "domain": ["geosite:category-ru"], "outbound": "direct" },
    { "ip": ["geoip:ru"], "outbound": "direct" }
  ],
  "defaultOutbound": "proxy"        // всё, что не попало в правила
}
```

Правило — это подмножество полей Xray (`domain`, `ip`, `port`, `network`, `protocol`, `process`) плюс `outbound ∈ {proxy, direct, block}`. Генератор конфига (`XrayConfigBuilder`) переводит пресет в секцию `routing` Xray. UI для простых правил — отдельные поля, плюс режим «сырой JSON» для продвинутых.

### 5.2 Встроенные пресеты

| Пресет | Логика | По умолчанию |
|---|---|---|
| **Всё через прокси** | private → direct, остальное → proxy | |
| **Всё, кроме RU** | private, `geosite:category-ru`, `geoip:ru` → direct; остальное → proxy | ✅ |
| **Только заблокированное** | `geosite:ru-blocked`, `geoip:ru-blocked` (и аналоги) → proxy; остальное → direct | |
| **Свой** | Копия любого пресета, которую пользователь редактирует | |

Встроенные пресеты хранятся в ресурсах сборки (`Presets/*.json`). Пользовательские хранятся в `%APPDATA%\SimpleVpn\presets\`. Импорт и экспорт пресета — JSON-файл или URL. Так администратор может раздать друзьям свой пресет, а пресеты не зависят от исполняемого файла.

> Названия категорий (`ru-blocked`, `category-ru`, `ru-available-only-inside` и т.д.) нужно сверить с актуальным релизом выбранного источника geo-баз, прежде чем зашивать их в пресеты.

### 5.3 DNS

Генерируется вместе с пресетом:
- для доменов, которые идут direct (`geosite:category-ru` и т.п.), используется прямой DNS (например, 77.88.8.8 / системный);
- остальные запросы идут через прокси на DoH (`https://1.1.1.1/dns-query`);
- `queryStrategy: UseIPv4`, если на сервере нет IPv6 (настраивается).

### 5.4 Задел под per-app (позже)

- В модели правил уже есть поле `process`, Xray поддерживает его на Windows и Linux (на Android — по UID).
- Правила по процессам имеют смысл только в TUN-режиме. В режиме прокси UI будет предупреждать об этом.
- UI: выбор запущенного процесса или .exe-файла.

## 6. Geo-базы и автообновление

- **Источник** (`GeoSource`): `{ name, geoipUrl, geositeUrl, checksumUrls? }`.
  По умолчанию — `runetfreedom/russia-v2ray-rules-dat` (последний релиз на GitHub, файлы `geoip.dat`, `geosite.dat` и `.sha256sum`). Альтернатива — Loyalsoldier/v2ray-rules-dat. Пользователь может указать свои URL.
- **Когда:** при старте приложения (если с прошлой проверки прошло больше интервала) и по таймеру. Интервал по умолчанию — 24 ч, настраивается; есть кнопка «Обновить сейчас».
- **Как:**
  1. Условный GET (`If-None-Match` / `If-Modified-Since`), чтобы не качать файл без изменений.
  2. Загрузка во временный файл → проверка sha256, если источник его предоставляет → проверка, что файл не пустой и парсится (минимальная валидация заголовка protobuf).
  3. Атомарная замена (`File.Replace`) в `%LOCALAPPDATA%\SimpleVpn\geo\`, старая версия хранится как `.bak` для отката.
  4. Если ядро запущено, оно перезапускается с новыми файлами (на 1–2 с); если перезапуск не удался — откат на `.bak`.
- **Если GitHub недоступен:** сначала попытка напрямую, затем через уже запущенный прокси (`127.0.0.1:<http-порт>`), если подключение активно.
- В сборку входит начальная копия geo-файлов, поэтому приложение работает сразу после установки, без сети.
- Скачиваются только `.dat`-файлы, а не исполняемый код, поэтому скомпрометированный источник подменит только списки, но не сможет выполнить код.

## 7. Импорт серверов

- Парсер `vless://` (`VlessLinkParser`) поддерживает: `security=tls|reality|none`, `type=tcp|xhttp|ws|grpc|httpupgrade`, `sni`, `fp`, `alpn`, `pbk`, `sid`, `spx`, `flow`, `path`, `host`, `mode`, `extra` (JSON для XHTTP), `#имя`.
- Неизвестные параметры сохраняются в профиле как есть, чтобы не терять их при экспорте обратно в ссылку.
- Источники: вставка текста, буфер обмена (проверяется при открытии окна добавления), QR-код из файла-картинки или со снимка экрана (ZXing.Net).
- Архитектурный задел: интерфейс `IProfileSource` → `LinkSource` (сейчас) и `SubscriptionSource` (позже, 3x-ui subscription, base64-список ссылок). Позже можно добавить `vmess://`, `trojan://`, `ss://`.

### Ключевой поток «Подключить»

```
UI (кнопка) → ConnectionManager.ConnectAsync()
  → проверка: выбран профиль? geo-файлы есть? для TUN — есть права? (иначе → IElevation)
  → XrayConfigBuilder.Build(profile, preset, mode, settings) → config.json
  → ICoreRunner.Start(config)  → ждём, пока inbound поднимется (порт слушается / TUN-адаптер создан)
  → mode == Proxy ? ISystemProxy.Enable(port) : —
  → State = Connected
```
Отключение выполняется в обратном порядке. При любой ошибке — откат того, что успело примениться.

| Что | Где |
|---|---|

| **M3 — geo** | GeoUpdater, расписание, источник по умолчанию + свой |
| **M4 — TUN** | Tun inbound, UAC-перезапуск, защита от утечек DNS |
| **M5 — удобство** | Трей, автозапуск, QR (импорт/показ), иконки стран, логи в UI, портативная сборка + установщик |
| **M6 — позже** | Per-app (process), подписки 3x-ui, статистика трафика, Android |

## 11. Риски и открытые вопросы

- **Антивирусы** могут ругаться на `xray.exe` и неподписанное приложение. Нужна инструкция для друзей; позже — подпись кода.
- **Изменения XHTTP** между версиями Xray: клиент и сервер (3x-ui) должны быть совместимы. Поэтому версия ядра фиксируется, обновление ядра — осознанный шаг.
- **Точные ключи TUN inbound** для зафиксированной версии Xray (`autoSystemRoutingTable`, `autoOutboundsInterface`, `dns` и т.д.) нужно проверить по [документации](https://xtls.github.io/config/inbounds/tun.html) до начала M4.
- **Android:** нужно выбрать способ встраивания Xray (AAR через биндинг или бинарник с передачей fd) — исследование перед M6.
- **Названия категорий** geosite/geoip в выбранном источнике нужно сверить перед M2.
- **Размер сборки** ~240 МБ (из них geo ~105 МБ, Xray ~35 МБ). Позже: триминг .NET, архив для раздачи, возможно — не класть geo в сборку, а качать при первом запуске.
- **Финальное название** приложения.
